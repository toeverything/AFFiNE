Ключевые принципы
1. Не форкайте AFFiNE глубоко — стройте поверх plugin/extension layer
AFFiNE/BlockSuite спроектирован как блок-редактор: каждый тип контента = кастомный блок со своей моделью данных и рендерером
Создайте ChartBlockSpec, KanbanBlockSpec, ExcalidrawBlockSpec — это позволит обновляться за апстримом
Ядро остаётся vanilla/BlockSuite store, UI на React
2. Local-first с CRDT — это ваше главное преимущество
Всё состояние — в Yjs doc: изменения работают офлайн и мержатся без конфликтов
Бэкенд хранит только снапшоты + обновления (updates log) — применяйте паттерн Y.encodeStateAsUpdate + периодические компактификации
Awareness для live-курсоров и presence
3. Канбан: логика Planka, реализация своя
Берём из Planka модель данных: boards → swimlanes → columns → cards, метки, дедлайны, вложения
Реализация на dnd-kit (лучший DnD для React, поддерживает несколько контейнеров и сенсоры)
Состояние карточек — тоже CRDT-узлы, чтобы drag-and-drop двух пользователей не конфликтовал
4. Графики: ECharts как headless-рендерер
Чарт-блок хранит: spec (ECharts option, JSON) + dataSource (ссылка на таблицу/CSV/API)
Редактирование — форма поверх спеки, не «голый JSON» (как в Miro: панель настроек слева)
Данные лениво загружаются при входе во вьюпорт — критично для больших досок
5. Производительность канваса — то, что отличает «игрушку» от Miro
Viewport-culling: рендерить только видимые блоки (affines/bounding-box culling)
Виртуализация колонок канбана и строк таблиц (TanStack Virtual)
Excalidraw-экземпляры выше N на вьюпорт → переключаться на статичный SVG-рендер (экспорт exportToSvg), интерактивный режим только на выбранном элементе
Для тысяч элементов — рассмотрите WebGL-слой (PixiJS) как режим «presentation zoom-out», ECharts умеет рендерить в canvas
6. Plugin SDK с первого дня
Miro побеждает marketplace'ом. Заложите:
Типизированный API: регистрация блоков, команд, панелей, контекстного меню
Sandboxed-исполнение плагинов (iframe + postMessage, или Web Workers + SES-компартменты для логики)
Событийная шина поверх CRDT-операций
7. Инфраструктура по best practices
Мультитенантность: schema-per-tenant
Права доступа: RBAC на уровне workspace → doc → блок (политики проверяются и на бэке, и на клиенте — CRDT документы нельзя «закрыть» только сервером, нужна шифрация блоков или серверная фильтрация updates)
Наблюдаемость: OpenTelemetry, метрики latency WS-соединений, APM для ECharts-рендеров (пользовательские лаги)
E2E: Playwright с мульти-пользовательскими сессиями — тестирование коллаборации это отдельная дисциплина
Совместимость форматов: экспорт в .excalidraw, PNG/SVG, Mermaid-импорт — дешёвый способ получить миграцию пользователей
Пошаговый план
MVP (2–3 мес): форк AFFiNE → кастомный Chart-блок (ECharts) + Kanban-блок (dnd-kit, без swimlanes) → WS-синк за AFFiNE-сервером
Коллаборация (1–2 мес): presence, курсоры, комментарии-треды привязанные к блокам, версионирование документов (Yjs snapshots + undo/redo per-user)
Масштабирование (1–2 мес): viewport-culling, виртуализация, read-only zoom-out, shared DB-ноды
Экосистема (ongoing): Plugin SDK → marketplace
