# Working in `blocksuite/crates/` (for agents)

`blocksuite/crates/` holds the pure BlockSuite CRDT document engine (`doc/`), the pure-Rust offline block preview kernel (`preview/`), the reusable editor library (`editor/`), the standalone playground application (`playground/`), and browser geometry/style oracle fixtures (`oracle/`).
These crates belong to the client Cargo workspace rooted at `packages/frontend/Cargo.toml`.

## Active Invariants (enforced now)

### Workspace boundaries
- `blocksuite/crates/doc` (`blocksuite-playground-doc`) & `bs-relay`: Pure CRDT document engine and binary room sync relay (`#![forbid(unsafe_code)]`, zero GUI/platform dependencies, `packages/frontend/scripts/check-invariants.sh` rejects `ui`, `wgpu`, `objc2`, and `web-sys` in `blocksuite/blocksuite/crates/doc/Cargo.toml`) built on `y-octo 0.4.0`. Preserves 53-bit `clientId` (`1..=2^53 - 1`), complete flavour schema defaults (`schema/`, 0 JS writeback updates on initial load), top-level Awareness `color` alongside `user` and `selectionV2`, deterministic `now_ms`-driven undo/awareness clocks (`session/`), WebSocket-only `seed-claim` / `seed-claim-result` single-winner arbitration (keyed by `seed:<docId>`), awareness refcounting across connections that forwards a removal (including the equal-clock live-to-`null` form `y-protocols` uses to expire a peer) once the last owner releases a client, `?ws=` relay origin forwarding with permissive blob CORS headers, and `wasm32-unknown-unknown` compatibility under `--no-default-features`. `read/` (`PageDocSession::read_page_snapshot`) is the typed read side: an ordered `PageSnapshot` tree of `BlockNode`s whose `BlockContent` covers every supported block flavour, keeps the normalized JSON of every `prop:*`, numbers `numbered` list runs, reads `prop:textAlign` and the note display modes by their BlockSuite wire values (`both` / `doc` / `edgeless`), reports blocks outside the root tree as `detached`, and reads any other flavour as `Unknown` instead of dropping it.
- `blocksuite/crates/preview` (`blocksuite-preview`): Pure-Rust offline preview kernel (`#![forbid(unsafe_code)]`, zero GUI/network/OS blocking I/O, zero host system font discovery or wall-clock calls). Provides `FontPool`, `SvgRasterizer`, `PinnedPixelCache`, `MermaidRenderer` (`merman` `resvg_safe`), pure in-memory RaTeX outline math rendering, `InMemoryTypstWorld`, `HayroPdfRenderer`, and `PreviewEngine`. All four worker features (`mermaid`, `math`, `typst`, `pdf`) compile independently on `wasm32-unknown-unknown` with `wasm-worker`, whose only exports are the four scalar `affine_worker_*` functions in `wasm_worker.rs` (`reset_input`, `push_input_u32`, `invoke`, `output_u32`) that `packages/frontend/hosts/web/src/wasm-scalar-rpc.js` calls through a raw `WebAssembly.instantiate`.
- `blocksuite/crates/editor` (`blocksuite-editor`): Reusable BlockSuite editor crate depending only on `blocksuite-playground-doc`, `blocksuite-preview`, `ui-kit`, `ui`, `ui-tokens`, and general utility crates (zero `affine-store` dependency and zero storage/network protocol leaks). Owns `theme` (backed by `ui-tokens` for colors, typography, icons, and `register_bundled_fonts`; on `wasm32` the fonts come from `register_web_font_bytes` instead, which rejects data with zero usable faces (`validate_font_bytes`), so the Wasm bundle embeds zero font bytes), `directory` (`WorkspaceDocDirectory` host port, `InMemoryDocDirectory`, and exact substring UTF-16 highlight matching), `block_flow/` (Page-mode renderer with LTR/RTL logical start/end placement), `rich_text/` (rich paragraph engine), `editor_session/` (selection and preedit core), `clipboard/`, `overlays/` (generic over `OverlayHost`), `surface/`, and `edgeless/` (generic over `EdgelessToolbarHost`).
- `blocksuite/crates/playground`: Standalone demonstration and verification host owning `PlaygroundView` (`lib.rs`, `chrome.rs`, `view_room.rs`), `room_client/` (live room sync), `showcase.rs` (deterministic `seed_showcase_doc` workspace), `PlaygroundView` glue for `editor_session/`, `overlays/`, and `edgeless/`, the native macOS desktop entry (`native-playground`), the WebAssembly canvas entry (`wasm_main`, which `web/index.html` calls after it fetched the seven `ui-tokens` fonts from `assets/fonts/` and passed each to `register_web_font`; both throw, and the page never reports ready, when a font has zero usable faces or the set misses one of `REQUIRED_FONT_FAMILIES`), and the deterministic headless verification CLI (`src/bin/bs_harness/`). It reuses the editor kernel and bundled fonts through `blocksuite-editor`, `ui-kit`, and `ui-tokens`.
- `unexpected_cfgs = "deny"` is enforced workspace-wide in `Cargo.toml`; dead upstream feature gates are forbidden.
- `blocksuite/crates/oracle/`: Browser-captured style and surface geometry fixtures (`style-oracle.json`, `surface-oracle.json`, `surface-baselines.json`, `surface-metrics-test.ttf`), `surface-baselines.mjs`, `surface-oracle.spec.mjs`, `extract-style-oracle.spec.ts`, and browser-mode `vitest.config.ts` (`browser.enabled: true` so `scripts/ci/vitest-node-projects.mjs` skips it).

### Page rendering and room sync
- **World space vs screen space**: `BlockFlow` lays a `PageSnapshot` out in document coordinates (origin at the page column's top-left, independent of window and scroll) and reuses the body of every block whose content, width and theme are unchanged. `PageViewport` maps world space onto the screen (`viewport origin + world - scroll`); only blocks intersecting the viewport become elements. Top bar, mode switcher, theme toggle and presence badges are screen-space chrome.
- **Style oracle parity**: Block metrics (`paragraph_spec` with baselines and heading letter spacing, quote/code/divider/bookmark constants, margin collapsing, 24px child indent, the 944px container with 96px / 24px side padding) mirror BlockSuite's page CSS and are asserted against `blocksuite/crates/oracle/style-oracle.json` in both themes by `blocksuite/crates/playground` tests, on the constants (L1) and on rendered frames (L2). Change a metric only together with the oracle.
- **Block semantics**: `prop:textAlign` (`left` / `center` / `right`) aligns paragraph and list text and is inherited by nested children that set none; a list prefix stays at the left edge. A collapsed heading hides its own children and the siblings under it up to the next heading of its level; a collapsed toggle hides its children.
- **First-line prefixes**: List bullets, numbers, checkboxes and toggles are placed against the first line of the item's text, and a numbered prefix sits on that line's baseline. Single-style labels (title, code, captions, cards) use the plain `InlineLayout`.
- **Snapshot ids**: `page.title_block`, `page.local_caret`, `page.selection`, `page.block.<blockId>`, `page.presence.<clientId>.caret|label`, `chrome.theme_toggle`, `chrome.presence.<clientId>`; block controls and overlays are listed under *Overlays and block controls*. A block, a control or a marker records its element snapshot only while it lies completely inside the page viewport; one cut by the fold is clipped on purpose.
- **Room sync**: `RoomProtocol` is the sans-I/O client of the relay's binary room protocol (`SyncStep1` / `SyncStep2` / `Update` document frames, awareness frames, unconditional reverse `Step2`) over a `DocState`. `connect` supplies the transport: `tokio-tungstenite` on a background thread natively (`--room <room> [--relay <ws_url>]`), a browser `WebSocket` on the Web (`?room=<room>&ws=<ws_url>`), both fetching image blobs from `/api/collection/{room}/blob/{sourceId}` (a bare HTTP/1.1 `GET` over TCP natively, `fetch` on the Web) and reconnecting with backoff. Native transports speak plain `ws://` / `http://` only: `wss://` / `https://` relays are rejected up front (`RoomConfig::validate_native`) and stay available on the Web. A reconnect re-announces local awareness two clocks ahead, above the tombstone the relay wrote when the previous connection dropped. Awareness renewal and expiry run on the scheduler clock, never the wall clock.
- **Images and blobs**: A blob present in the document state is decoded once (PNG, JPEG, WebP, GIF, BMP); bytes that are no such image stay `Image unavailable` and are never fetched again. A blob the page references but the relay does not have yet (an uploader writes `sourceId` before its upload finishes, and the relay announces no completed upload) is fetched again on the scheduler clock with a backoff doubling from 500 ms to a 4 s cap, for as long as the page references it and the room is not offline; ordinary document updates never restart a tracked fetch. The frame shows `Loading image`, then `Image unavailable` after three misses, and the image as soon as a retry finds it.
- **Remote selections**: Read only from `selectionV2` entries of the shown page, keyed `<pageId>` or `<pageId>:<managerId>` (split at the last colon, stricter than BlockSuite's prefix match); a selection in another page is never drawn.

### Page editing

- `EditorSession` keeps the anchor, focus, soft-wrap affinity and vertical navigation goal in document coordinates. The platform input handler exposes UTF-16 offsets within the focused block. Selection painting and IME candidate bounds use the same laid-out geometry as pointer hit-testing.
- A compound structural edit validates against a private copy before committing once to the tracked blocks undo stack. Changing flavour creates a fresh block for live JS models. Edits within a flavour retain the block identity. Cross-block deletion, IME preview and clipboard slices follow the full tree order within Page-visible notes, including collapsed content. Subtrees after the endpoint survive. A range starting in code places those subtrees immediately after the code block. Numbered Markdown lists accept zero as a starting number and continue a preceding numbered sibling when present. Typing within the 500 ms scheduler-clock capture window coalesces. Undo and redo resolve stored relative positions in the title or block text. Local commits publish document updates and selection changes publish awareness under `<pageId>:native`; a selection that is dropped publishes that entry empty, so peers stop drawing the caret and keep the name and color. Preedit temporarily replaces the selected text in the displayed snapshot. Cancellation restores the directional range. Only a commit writes text. Editing the page title also updates workspace page metadata.
- Clipboard slices carry BlockSuite JSON, HTML and plain text. macOS publishes UTF-8 text and `public.html` and reads HTML-only pasteboard items. Web clipboard events expose HTML and the BlockSuite MIME type. HTML includes the LZ-String URI-encoded `data-blocksuite-snapshot` for lossless block properties, child blocks and inline references. The slice preserves shared text types in nested properties. Pasting into one text block preserves relative positions in its untouched suffix.
- A text-only edit refreshes the changed block's text and reuses the other laid-out bodies. Remote updates preserve the screen position of the reading anchor when its block survives. On Linux headless with 10,000 blocks at 1280 × 800, cold layout and frame took 284.078 ms median / 328.501 ms p95. A keystroke in paragraph 5000 and its frame took 17.793 / 19.454 ms and laid out one block. A steady viewport frame including pixel readback took 10.691 / 16.928 ms. These are observed timings. The single-block work count is enforced by the benchmark.

### Overlays and block controls
- **Who owns what**: `EditorSession` owns the text selection, the caret and every text edit. `Overlays` (`overlays/`) owns what floats above or reacts inside the page: the slash menu, the formatting toolbar, the drag handle with its drop indicator, hover, and the block controls. The overlays read the selection (as a `SelectionFormat`: its world-space box, the marks every selected unit carries, the shared alignment) and never paint a caret or a selection of their own.
- **Data in, commands out**: `Overlays` takes an `OverlayScene` (page snapshot, world-space layout, window geometry) with an `OverlayEvent` or a key, and answers with `OverlayEffects`. The `PlaygroundView` glue in `overlays/{view,view_edits}.rs` feeds it input and carries the effects out; `lib.rs`, `chrome.rs` and `block_flow/` only carry hooks (`PagePaint` into `page_elements`, the page-layer elements and popovers into the element tree, listeners). `PlaygroundView::dispatch_overlay` is the entry for pointer listeners and for hosts and tests (`OpenSlashMenu`, `SetSlashQuery`, `SetSelection`, ...); `SetSelection` sets the editor's selection.
- **Pointer and keys**: A press on the page dismisses the slash menu, the link field (unapplied) and a block drag, then goes to the editor; pointer moves and the release are handled at the window root, so a drag continues outside the page. The formatting toolbar waits while the button of a plain press is held and opens on release; a double or triple click opens it at once. Keys reach one handler, `editor_key_down`, which first offers them to the overlays: an open link field takes every key but the ones that type text, the slash menu takes `Up`, `Down`, `Tab`, `Shift+Tab`, `Enter` and `Escape` (`Tab` steps through the items and never indents the block; when triggered in-document with no matching items, `Enter`, `Up`, and `Down` close the menu and pass through to the editor), and everything else is the editor's. A pointer on an open popover does not change which block is hovered under it.
- **Edits are single undo steps**: Every overlay edit goes through the editor's `PageDocSession`, stores the selection for undo, and is published like any editor commit. Marks use the editor's `format_mark`; a link and an alignment run in one `structural_edit` across the selected paragraph and list blocks; a to-do box, a collapse and a drop are isolated between `stop_capturing` calls, the drop through `reparent_block` so numbered runs are renumbered. A slash command is one `structural_edit`, following BlockSuite's `updateBlockType` and `appendDivider`: it removes the typed `/filter`, then a paragraph type, a list type or code converts the block with whatever text it has left (in place within a flavour, as a fresh block across flavours; a block without text of its own gets the new block below instead), and a divider goes right below the block, followed by an empty paragraph to type in when the block was the last of its parent. The caret stays where the command was typed, or moves to the block after a divider. One undo restores the typed command.
- **Positioner**: `place_popover` is pure and works in screen space below the top bar: `Above` (formatting toolbar, centered on the selection) and `BelowStart` (slash menu, at the caret) flip to the other side when the preferred one would come closer than the edge margin to the top bar or the window bottom, and clamp horizontally inside the margins. Results are on the pixel grid.
- **Overlay motion**: Popovers fade over 150 ms with an ease-out cubic `EaseOut` evaluated at scheduler time. An opening popover mounts on its first frame at zero opacity so its hitboxes are live immediately; a closed popover at zero opacity is unmounted, and one fading out carries no listeners and is dropped when the fade ends. Disclosure chevrons turn over the same 150 ms. Nothing here loops per frame.
- **Slash menu** (`overlay.slash_menu`, rows `overlay.slash_menu.item.<id>`, `.group.<name>`, `.query`, `.empty`): Typing `/` at a caret in paragraph or list text, outside inline code, opens it on that character, remembered as a relative position (`EditorSession::slash_trigger`): text a peer inserts before the `/` moves the menu along. The text between the `/` and the caret is both document text and the filter (`query_in_document`); the menu closes when the caret leaves that text, whitespace follows the `/`, or the character at the position is no longer that `/` (deleted, or deleted and typed again by a peer), and a command never runs on text it did not open on. `Escape` leaves the text as typed. `OpenSlashMenu` opens the menu with a filter of its own, shown in a query row and edited by the menu's keys. Filtering uses case- and whitespace-insensitive subsequence matching (`isFuzzyMatch`); without matches the list keeps a `No results` row. Items follow BlockSuite's order in two groups (`Basic`: text, the six headings, code block, quote, divider, new doc [`SlashCommand::NewDoc`], linked doc [`SlashCommand::LinkedDoc`]; `List`: bulleted, numbered, to-do, toggle); all six headings stay in the list itself so each is one filter away. Each icon sits in a bordered 28 px box, rows are 44 px (title plus description subtitle, with group headers hidden while filtering), and the menu has no border, only its shadow.
- **Linked-doc `@` menu** (`overlay.linked_doc_menu`, rows `overlay.linked_doc_menu.item.<idx>`, `overlay.linked_doc_menu.create`): Typing `@` anywhere in paragraph or list text (outside inline code), or typing `[[` or `【【` (which converts the pair into `@`), opens the linked-doc popover anchored at the caret (`EditorSession::linked_doc_trigger`), querying the active `WorkspaceDocDirectory` as the user types. `Up`/`Down` move selection across matched docs and the trailing Create row, `Enter` selects or creates the linked doc and replaces `@query` with a BlockSuite `InlineReference` (`LinkedPage`) chip in one undo step, and `Escape` closes the menu while leaving the typed text intact.
- **Formatting toolbar** (`overlay.format_toolbar`, buttons `.bold`, `.italic`, `.underline`, `.strike`, `.code`, `.link`, `.align_left|center|right`, link field `.link_input`, `.link_apply`, `.link_remove`): shown above a finished, non-empty selection of paragraph and list text, single-block or across blocks, while no composition runs and no slash menu is up; a selection touching the title or code gets none. A mark button is active only when the whole selection carries the mark. Alignment goes on every paragraph and list block the selection touches, empty ones included, and a block that sets none reads as its nearest aligned ancestor's. The link field is a one-line text input of its own (`LinkBar`: text, selection, composition). While it is open it is the view's text input: every `EntityInputHandler` call goes to it, `editor.composing()` stays false, and the document's text, selection and composition are untouched until `Apply`; opening, closing and every change of it are reported with `notify_text_input_changed`. Caret keys, deletion, select-all, copy and cut are the field's, `Escape` abandons a composition before it closes the field, and a keyboard paste reads the clipboard where the platform can; in a browser the key keeps its default action so the `paste` event that follows reaches the field. It has the only caret; the document keeps showing the selection.
- **Equation editor** (`overlay.equation_editor`, `.input`, `.done`): opens on `$$$$ ` / `$$$$ Enter` (block `affine:latex`), `$$ ` / `$$ Enter` (empty inline equation), or clicking an existing `FlowKind::Latex` block or `DecorationKind::LatexChip`. `Enter`, clicking `Done`, and clicking outside the popover commit the current LaTeX string (including any active IME composition via `LinkBar::into_committed_text`), while unchanged content closes without writing; `Escape` cancels and closes without writing. Open inline targets track remote peer edits via a zero-width CRDT `SelectionSnapshot` identity check and auto-close if the target is deleted or replaced remotely. The input field paints syntax-colored LaTeX directly from `highlight_line` runs, supports `Up`/`Down` navigation across soft-wrapped visual lines, and maps pointer clicks (`EquationClick`) to the nearest UTF-16 offset on the clicked visual row.
- **Mobile keyboard toolbar & bookmark prompt** (`overlay.keyboard_toolbar`, buttons `overlay.keyboard_toolbar.<id>`, docked panel `overlay.keyboard_toolbar.panel.<group>.<id>`, and `overlay.bookmark_prompt`, `.input`, `.apply`, `.cancel`): mirrors `0.27.5` `defaultKeyboardToolbarConfig` (`More` 8-group scrollable tool panel, horizontally scrollable top-level / `Aa` item strip without `...` pagination, `Aa` `textSubToolbarConfig` with `autoShow` on non-collapsed text selections, `Turn into` reusing `SLASH_ITEMS`, and `Highlight` foreground/background swatches). While `KeyboardToolbar` is visible on mobile, the floating desktop `FormatToolbar` is suppressed unless its inline link field is explicitly opened (`KeyboardToolbarAction::Link`). Date actions and `embed-linked-doc` `"Updated YYYY-MM-DD HH:MM"` card labels format against the host's local calendar timezone (`utc_offset_minutes`); `Image` opens the host file picker (`can_pick_images` hides the button on native hosts without a registered picker), queues background upload of the base64url SHA-256 content-addressed blob (retrying on scheduler backoff and reconnect until confirmed), and publishes `affine:image`; `Bookmark` opens `overlay.bookmark_prompt` and commits an `http(s)://` `affine:bookmark` block as one undo step (`Escape`, `Cancel`, outside press, empty input, or relative paths write zero blocks).
- **In-place table cell editing** (`page.table_cell_focus`): `affine:table` cells lay out and paint with `RichParagraph` (preserving bold, italic, underline, strike, inline code, links, and inline math) and carry their `FlowTextLayout` for same-source hit-testing, caret, selection, `character_index_for_point`, and IME candidate bounds. Clicking a cell focuses it directly in place (1.5 px brand border, zero floating popover, zero writeback on focus-only). Typing, deleting, and pasting splice the cell's live `Y.Text` directly via `PageDocSession::splice_table_cell_text` (applying the shared `insertion_marks_at` rule so text typed after inline code, links, references, or math never leaks into those marks, and sharing `AnchoredInlineInput` + `Utf16ImeBuffer` with `EdgelessLabelEditor`). Keystrokes coalesce within the 500 ms undo window, refresh only the table block in O(1) via `PageDocSession::read_table_block` with zero `TableData::clone()`, and mark only the table block in `dirty_text`. IME preedit splices via `split_delta` so surrounding marks keep identical pixels; clicking inside an already-focused inline target (table cell or Edgeless label) commits any in-flight composition via `unmark` into its original replacement range before repositioning the caret (whereas body `change_selection` clears in-flight composition on click). `Enter`/`Shift+Enter` insert `\n`, `Tab`/`Shift+Tab` stay consumed inside the cell, `Up`/`Down` step across visual lines, and `Escape`, mode switches, or remote deletion exit through `finish_inline_targets` (closing the undo window and suppressing unselected root-title fallback input until the user re-selects a target). While a table cell is focused without a body selection, `KeyboardToolbar` mark/block buttons render disabled; explicit cell mark toggling and `pending_marks` are deferred until body and cell selections unify.
- **Drag handle** (`overlay.drag_handle`, `overlay.drop_indicator`): mounted only for the hovered or dragged block, 24 px left of the block and never closer than 4 px to the window edge. Inside its 24 px target it draws BlockSuite's Page-mode grabber: a 4 × 12 px vertical bar while the pointer is on the block's row, narrowing to a 2 × 12 px vertical bar once hovered or dragged (the 2 × 3 six-dot 14 px pill is reserved for Edgeless `gfx` drag handles). A heading keeps the place beside its text for its collapse chevron: its handle sits one step further out, and is left away where the gutter has no room for both. A drag targets the nearest slot among the block's own siblings.
- **Block controls**: `page.block.<id>.checkbox`, `.toggle` and `.collapse` are 24 px targets over the to-do box, the toggle chevron and the heading chevron (an expanded heading shows its chevron only while the pointer is on its row); `page.block.<id>.copy` appears on a hovered code block and reads `Copied` for 1.5 s on the scheduler clock. A sideways scroll over an unwrapped code block scrolls its lines inside `BlockBody::code_scroll` instead of the page; the caret, the selection, the bounds given to the input method, collaborators' carets and selections (translated per highlight span's own block scroll before clamping), and pointer hit-testing follow that scroll and stay inside the code area (`ScrolledCode`), and moving the caret scrolls it into view.
- **Sizes and radii**: Interactive targets are at least 24 × 24 px (toolbar buttons 28 × 28, edge to edge). Rows and buttons round concentrically with their container: 8 px menu with 4 px padding and 4 px rows (BlockSuite pads its menu `8px 4px 8px 8px`; 4 px all around keeps the radii concentric), 8 px toolbar with 4 px padding and 4 px buttons (`gap = 2px, pad = 4px`, intentionally compact relative to JS `8px / 0 6px` so the toolbar fits a 320 px window between its 8 px margins). The toolbar is 297 px wide, with 8 px on either side of the line between the mark and the alignment buttons.
- **Verification**: `bs-harness render --state <name>` renders one overlay state of the showcase, `bs-harness audit-states` audits every state in both themes at `1280` and `320` px, and `bs-harness record-demo <dir>` writes the frames of a 60 fps walk through typing, composition, the slash menu, the toolbar and the block controls; all drive the view through input events, the input handler and `dispatch_overlay` only.

### Rich paragraph layout
- **Variable-font slant axis**: CoreText and Swash specialize an upright variable face at its minimum OpenType `slnt` coordinate for italic and oblique requests, alongside `wght`. A native static italic face retains its own outlines. Pixel letter spacing shifts shaped clusters and their total advance together.
- **`RichParagraph`**: The single rich-text engine: `BlockFlow` lays out and paints paragraph and list text with it (`LaidOutRichParagraph::paint_at`, the same path `RichParagraphElement` uses), and reads remote carets and selections from its geometry. Cursor and selection geometry uses source UTF-16 positions and extended-grapheme boundaries. Each inline reference occupies one document unit regardless of its resolved label width, wraps as one inline object (the words before it stay on their line), and its prefix is the generated `LinkedPageIcon` SVG painted at the `DecorationKind::PageGlyph` bounds. `color` and `background` marks resolve through the theme (`DecorationKind::Highlight` behind the glyphs), and bold follows CSS `bolder`. Shaped lines supply wrapping, painting, hit targets, and both caret affinities at a soft wrap.
- **Inline style parity**: Code boxes and links follow the light/dark theme tokens and browser measurements in `blocksuite/crates/oracle/style-oracle.json`; the code box metrics are constants that a test keeps equal to the oracle, so the oracle JSON is never embedded in the shipped binary. Plain and rich renders of one document can be reproduced with `bs-harness render-rich-sample --out-plain plain.png --out-rich rich.png`.

### Edgeless spatial canvas and interactive authoring
- **Spatial camera & canvas (`edgeless/`)**: `edgeless/camera.rs` (`EdgelessCamera`) manages pan/zoom (`[0.1, 6.0]`), cursor-anchored wheel zoom, and fit-to-bounds (initialized before building `chrome.edgeless_zoom` so Frame 1 displays the fitted zoom percentage). `edgeless/scene.rs` and `edgeless/canvas_paint.rs` prepare and render Surface-parented Frames and EdgelessText and root-parented Notes in a single snapshot pass. Note dimensions are world units. Layout uses the logical width divided by scale. Collapsed notes clip to the stored world height, which already includes scale. The canvas merges the block and vector paint streams by fractional index and Frame/Group ancestry (`prop:childElementIds` treats every present key as a frame member, and equal indices preserve source enumeration order within each stream — live incremental sync and independent multi-author merged updates follow `(Reverse(client), clock)` integration order, whereas a late-join single V1 snapshot with cross-client causal edits among equal-index overlapping elements can invert their tie-break paint/pick order until `y-octo` exposes per-map integration order). Equal indices continue the active stream, with blocks first at the start. Notes reuse their cached `BlockFlow::layout_nodes` during pan/zoom. All items paint under `edgeless.viewport`, with bottom-centered creation toolbar (`chrome.edgeless_toolbar`) and bottom-right screen-space zoom controls (`chrome.edgeless_zoom`, stacked cleanly above `chrome.edgeless_toolbar` on narrow viewports `< 660 px`). `bs-harness render --mode edgeless [--zoom <f32>] [--pan <x>,<y>]` renders spatial states, `bs-harness audit-states` audits Edgeless default + `0.5x` + `2.0x` + authoring states (`edgeless_selected`, `edgeless_marquee`, `edgeless_inline_edit`, `edgeless_authoring`) in Light/Dark at `1280` and `320` px, and `bs-harness bench` measures `edgeless_1k_pan_zoom_frame_ms` and asserts `edgeless_1k_pan_zoom_blocks_relayout == 0`.
- **Edgeless interactive authoring & inline IME editing (`edgeless/{toolbar,hit_test,overlay,label_editor,inline_edit,gestures,commit,commands}.rs`)**: `chrome.edgeless_toolbar` provides Select (`V`/`Escape`), Hand (`H` or holding `Space`), Note (`N`), Shape (`S` with rect/ellipse/diamond/triangle/rounded-rect picker), Connector (`C` with cardinal port snapping and live connector preview), Brush (`P`), Highlighter, Text (`T`), and Frame (`F`, populating `prop:childElementIds`). World-space hit-testing walks exact reverse paint order (inverse-rotated OBBs for shapes/texts, routed polyline distance from `SurfaceLayout` for connectors/strokes, exact `layout_inline` title pill and border for frames). Selection renders a screen-crisp `edgeless.selection_box`, 8 resize handles (`edgeless.handle.nw..w`), top rotation handle (`edgeless.handle.rotate`, `15°` snap with `Shift`), and `2×3` 6-dot `14px` Edgeless `gfx` drag handle (`edgeless.drag_handle`) on selected blocks; resize and rotation handles are suppressed while inline label editing is active, and the underlying static label is hidden until commit. Dragging, resizing, rotating, deleting (`Backspace`/`Delete`), and z-reordering (`[`/`]` via `fractional-indexing@3.2.0` keys in `blocksuite/blocksuite/crates/doc/src/fractional_index.rs`) commit single atomic undo steps on `PageDocSession` and broadcast over `RoomProtocol`. Double-clicking a Note or EdgelessText edits rich text inline via `EditorSession` + `EntityInputHandler` with camera-mapped `bounds_for_range`; double-clicking a Shape, Connector, SurfaceText, or Frame title edits its `Y.Text` inline (`edgeless.inline_edit`) with full UTF-16 + IME preedit support (clicking inside an active inline label commits any in-flight composition via `unmark` into its original replacement range before placing the caret, while body `change_selection` clears in-flight composition on click).

### Surface reading and painting

- `BlockContent::Surface` retains the element count and exposes typed elements sorted by fractional index in wire creation order (matching `(Reverse(client), clock)` integration order for live incremental sync and independent multi-author merged updates, with the late-join cross-client causal tie-break caveat noted above). Each element keeps all normalized wire properties and unknown types (`textDisplay` on shapes is `@local()` and defaults to `true` locally without reading from the wire). Straight connector labels interpolate linearly (`Vec.lrp`), orthogonal labels follow polyline distance, and curved labels follow the cubic Bézier parameter. Connector labels retain their stored size and follow the route at the label offset. When `labelXYWH` is absent, the native renderer measures the label at paint time. This extends BlockSuite’s `hasLabel()` behavior with zero document writebacks.
- `surface::layout_surface` accepts element snapshots and world bounds for external blocks. It finds ports on rotated shape outlines and routes orthogonal connectors using their two endpoint bounds. The router follows BlockSuite's `ConnectorPathGenerator`. A connector's `rough` flag enables jitter and `roughness` sets its amplitude. Scribbled shapes follow RoughJS hachure, `pointsOnPath` sampling and seeded operation order. Brush and highlighter share the perfect-freehand pressure outline and midpoint quadratic curves. EdgelessCanvas caches geometry by document revision, theme and environment revision. Fully visible elements emit `edgeless.surface.<id>` in screen coordinates. The standalone harness uses the same painter.
- The canvas clips its viewport in screen coordinates. Within the camera transform, each rotated shape or text pushes its own center rotation before its label mask. The GPU inverse-maps coverage into the label's local coordinates while retaining the screen-space viewport clip.

- The JS surface oracle runs the BlockSuite shape, connector and freehand implementations and compares their coordinates to `blocksuite/crates/oracle/surface-oracle.json`. Rust tests consume the same geometry and font baselines.
- With repository JavaScript dependencies installed, `cargo test --locked -p blocksuite-playground-doc --example bs_doc_driver js_authored_surface` verifies data and rich-text marks written by Yjs against the typed Rust snapshot and compares the encoded document before and after reading.

### Rust Module Organization & Fast Verification
- **Proactive modularization**: Split files by responsibility (targeting ~500–800 production lines; promote `<name>.rs` to `<name>/mod.rs` when introducing submodules). Keep each `mod.rs` as the dependency and visibility hub (`pub(super) use ...`), import siblings via `use super::...`, and hoist cross-layer shared items to the narrowest common ancestor `mod.rs`.
- **Global optimum & clean boundaries**: Prefer structural cleanup and bold deletion over band-aid patches. Delete obsolete code outright, fold single-caller one-way fragments back into their caller, and extract shared helpers only for stable domain concepts, genuine multi-site reuse, or key invariants — never for one-line expressions.
- **Focused, table-driven tests**: Keep test-only imports and helpers inside `#[cfg(test)] mod tests`, placing unit tests in the file under test and cross-submodule tests in the lowest common `mod.rs`. Keep every test file and function name aligned with its actual assertion scope, and group similar scenarios into table-driven loops rather than proliferating near-identical `#[test]` functions.
- **Sub-60-second verification loop**: Validate uncertain paths with minimal focused spikes first and remove scaffolding before landing. Keep routine edit-verify turns under **60 seconds** using targeted `cargo check --locked -p ...` / `cargo test --locked -p ... --lib <filter>` and `./packages/frontend/scripts/check-invariants.sh` (which enforces `super::super` bans, `mod.rs` layout, orphan-file detection, and per-file LOC limits automatically alongside `rustfmt.toml`).

- **Standalone Web preview staging (`playground/scripts/stage-web.mjs`)**: Stages `wasm-scalar-rpc.js`, `workers/preview-worker-core.js`, `workers/{math,pdf,mermaid,typst}-worker.js`, built preview `.wasm` binaries, `pkg/playground.{js,_bg.wasm}`, and the `ui-tokens` fonts (`assets/fonts/*.ttf`) into `blocksuite/crates/playground/web/` (`node blocksuite/crates/playground/scripts/stage-web.mjs <built-wasm-dir> [--out <dir>]`) and validates relative ESM imports.
- **Whiteboard `mindmap` & `gfx/text` `RE_RTL_CHECK` compatibility**: `SurfaceElementKind::Mindmap` decodes `layoutType` (`Right`/`Left`/`Balance`), `style` (`1..=4` `0.27.5` `StrokeColorShortMap` medium palettes), and `children` (`{ index, parent?, collapsed? }`) with zero CRDT writeback, synthesizing `0.27.5` branch and `6px` collapsed-stub connectors (`surface/mindmap.rs`) beneath child shapes and falling back to deterministic `compute_mindmap_layout` when child shapes share an unpositioned origin (interactive Mindmap authoring/editing remains future work).
