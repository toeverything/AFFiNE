# Working in `blocksuite/native-playground` (for agents)

This document records the active engineering invariants enforced in CI today alongside the planned contracts for upcoming crates and editor features.

## Active Invariants (enforced now)

### Workspace boundaries
- `crates/ui`: Single fused internal GPU UI library (vendored once without upstream sync hooks, zero internal `proc-macro = true` crates, zero external UI-kit dependencies). It knows **nothing** about BlockSuite or AFFiNE (`scripts/check-invariants.sh` rejects `blocksuite` and `affine` inside `crates/ui`) and embeds zero fonts (fonts are registered by the application via `cx.text_system().add_fonts(...)`).
- `crates/doc` (`blocksuite-playground-doc`) & `bs-relay`: Pure CRDT document engine and binary room sync relay (`#![forbid(unsafe_code)]`, zero GUI/platform dependencies — `scripts/check-invariants.sh` rejects `ui`, `wgpu`, `objc2`, and `web-sys` in `crates/doc/Cargo.toml`) built on `y-octo 0.3.0`. Preserves 53-bit `clientId` (`1..=2^53 - 1`), complete flavour schema defaults (0 JS writeback updates on initial load), top-level Awareness `color` alongside `user` and `selectionV2`, deterministic `now_ms`-driven undo/awareness clocks, WebSocket-only `seed-claim` / `seed-claim-result` single-winner arbitration (keyed by `seed:<docId>`), awareness refcounting across connections that forwards a removal (including the equal-clock live-to-`null` form `y-protocols` uses to expire a peer) once the last owner releases a client, `?ws=` relay origin forwarding with permissive blob CORS headers, and `wasm32-unknown-unknown` compatibility under `--no-default-features`. `read.rs` (`PageDocSession::read_page_snapshot`) is the typed read side: an ordered `PageSnapshot` tree of `BlockNode`s whose `BlockContent` covers every supported block flavour, keeps the normalized JSON of every `prop:*`, numbers `numbered` list runs, reads `prop:textAlign` and the note display modes by their BlockSuite wire values (`both` / `doc` / `edgeless`), reports blocks outside the root tree as `detached`, and reads any other flavour as `Unknown` instead of dropping it.
- `crates/playground`: Application layer owning the shipping `PlaygroundView`, the tracked repository font registration (`Inter` and the four `IBM Plex Mono` faces), the native macOS desktop entry (`native-playground`), the WebAssembly canvas entry (`wasm_main`), and the deterministic headless verification CLI (`bs-harness`). `theme.rs` resolves colors, typography and icons from the generated `tokens/tokens.rs` / `tokens/icons.rs` (pulled in with `include!`, never copied and never reformatted) for `PlaygroundTheme::{Light, Dark}`; `block_flow.rs` is the Page-mode renderer; `rich_text.rs` is the rich paragraph engine; `editor_session.rs` and `clipboard.rs` are the page editor; `overlays.rs` holds the popovers and the interactive block controls; `room_client.rs` is live room sync. Without a room the view shows the deterministic `seed_showcase_doc` workspace (every Page-mode block, one image blob, one remote collaborator).
- `unexpected_cfgs = "deny"` is enforced workspace-wide in `Cargo.toml`; dead upstream feature gates are forbidden.

### Platform matrix
`crates/ui` compiles cleanly across three targets from one crate:
- **macOS (`target_os = "macos"`)**: AppKit + Metal + CoreText, including windowless `MetalHeadlessRenderer` readback, full mip-0 `MetalAtlas` zero-init, and offscreen `MacWindow` frame/scale fallbacks.
- **Linux Headless (`target_os = "linux"`)**: `wgpu` + `cosmic-text` via `WgpuHeadlessRenderer` on Mesa `lavapipe` for deterministic software rasterization in CI.
- **Web (`target_family = "wasm"`)**: Single-threaded `wasm32-unknown-unknown` + WebGPU/WebGL2 + `CanvasFontFallback` + block-scoped `ImeMirror` (no `wasm_thread`, no `http_client`), verified in headless Chromium via `scripts/web-smoke.mjs` (`--query` loads the page with a query string such as a live room, `--min-title-ink` waits for that much page ink before capturing; without a query it also drives composition across blocks and composition and paste in the toolbar's link field through the hidden textarea).

### Determinism, single clock, and zero tester branches
- **Single UI execution path**: Headless shell rendering (`bs-harness render`), desktop (`main.rs`), and Web (`wasm_main`) all instantiate and render the exact same shipping `PlaygroundView` through `Application::with_platform(...)` and `Window::draw()`.
- **No wall clock outside `crates/ui/src/platform/`**: `Instant::now()` and `SystemTime::now()` are forbidden anywhere outside `crates/ui/src/platform/` (`scripts/check-invariants.sh`). Host thread-park deadlines read monotonic time in `crates/ui/src/platform/clock.rs`; animations and transitions read the scheduler clock (`cx.background_executor().now()`, backed by `TestScheduler` in headless/test runs and the platform scheduler in desktop/web).
- **Motion is pure data**: Transitions are declared once as `(from, to, curve, start_ms, duration_ms)` and evaluated as a pure function of scheduler time. Never write frame-by-frame recurrence loops or `sleep` waits.
- **Zero tester branches**: Application and layout logic never inspect `is_headless` or inline `#[cfg(any(test, feature = "harness"))]` to alter behavior (`scripts/check-invariants.sh`).
- **Four-rate replay invariance**: Stepped `PlaygroundView` transitions (the mode switch, the slash menu and the formatting toolbar opening and closing) must progress monotonically with in-flight frames and produce byte-identical terminal `FrameSnapshot` JSON at `60`, `120`, `24`, and `7` fps (`bs-harness fps-check`).
- **Callsite tracing**: Under the `harness` feature, `InteractiveElement::snapshot(...)` records post-layout bounds, `content_mask`, interactivity, focus, and `#[track_caller]` `file:line` origins into `Window::frame_snapshot()` for `sources_at(x, y)` and `bs-harness audit`. Non-harness release builds compile to no-op stubs.
- **Locked builds & rustflags isolation**: `Cargo.lock` is committed and CI runs with `--locked` and `CARGO_ENCODED_RUSTFLAGS=""` (`scripts/check-invariants.sh` verifies fresh `cargo rustc --print link-args` contains zero leaked root NAPI flags).

### Page rendering and room sync
- **World space vs screen space**: `BlockFlow` lays a `PageSnapshot` out in document coordinates (origin at the page column's top-left, independent of window and scroll) and reuses the body of every block whose content, width and theme are unchanged. `PageViewport` maps world space onto the screen (`viewport origin + world - scroll`); only blocks intersecting the viewport become elements. Top bar, mode switcher, theme toggle and presence badges are screen-space chrome.
- **Style oracle parity**: Block metrics (`paragraph_spec` with baselines and heading letter spacing, quote/code/divider/bookmark constants, margin collapsing, 24px child indent, the 944px container with 96px / 24px side padding) mirror BlockSuite's page CSS and are asserted against `tokens/style-oracle.json` in both themes by `crates/playground` tests, on the constants (L1) and on rendered frames (L2). Change a metric only together with the oracle.
- **Block semantics**: `prop:textAlign` (`left` / `center` / `right`) aligns paragraph and list text and is inherited by nested children that set none; a list prefix stays at the left edge. A collapsed heading hides its own children and the siblings under it up to the next heading of its level; a collapsed toggle hides its children.
- **First-line prefixes**: List bullets, numbers, checkboxes and toggles are placed against the first line of the item's text, and a numbered prefix sits on that line's baseline. Single-style labels (title, code, captions, cards) use the plain `InlineLayout`.
- **Snapshot ids**: `page.title_block`, `page.local_caret`, `page.selection`, `page.block.<blockId>`, `page.presence.<clientId>.caret|label`, `chrome.theme_toggle`, `chrome.presence.<clientId>`; block controls and overlays are listed under *Overlays and block controls*. A block, a control or a marker records its element snapshot only while it lies completely inside the page viewport; one cut by the fold is clipped on purpose.
- **Room sync**: `RoomProtocol` is the sans-I/O client of the relay's binary room protocol (`SyncStep1` / `SyncStep2` / `Update` document frames, awareness frames, unconditional reverse `Step2`) over a `DocState`. `connect` supplies the transport: `tokio-tungstenite` on a background thread natively (`--room <room> [--relay <ws_url>]`), a browser `WebSocket` on the Web (`?room=<room>&ws=<ws_url>`), both fetching image blobs from `/api/collection/{room}/blob/{sourceId}` (a bare HTTP/1.1 `GET` over TCP natively, `fetch` on the Web) and reconnecting with backoff. Native transports speak plain `ws://` / `http://` only: `wss://` / `https://` relays are rejected up front (`RoomConfig::validate_native`) and stay available on the Web. A reconnect re-announces local awareness two clocks ahead, above the tombstone the relay wrote when the previous connection dropped. Awareness renewal and expiry run on the scheduler clock, never the wall clock.
- **Images and blobs**: A blob present in the document state is decoded once (PNG, JPEG, WebP, GIF, BMP); bytes that are no such image stay `Image unavailable` and are never fetched again. A blob the page references but the relay does not have yet (an uploader writes `sourceId` before its upload finishes, and the relay announces no completed upload) is fetched again on the scheduler clock with a backoff doubling from 500 ms to a 4 s cap, for as long as the page references it and the room is not offline; ordinary document updates never restart a tracked fetch. The frame shows `Loading image`, then `Image unavailable` after three misses, and the image as soon as a retry finds it.
- **Remote selections**: Read only from `selectionV2` entries of the shown page, keyed `<pageId>` or `<pageId>:<managerId>` (split at the last colon, stricter than BlockSuite's prefix match); a selection in another page is never drawn.

### Page editing

- `EditorSession` keeps the anchor, focus, soft-wrap affinity and vertical navigation goal in document coordinates. The platform input handler exposes UTF-16 offsets within the focused block. Selection painting and IME candidate bounds use the same laid-out geometry as pointer hit-testing.
- A compound structural edit validates against a private copy before committing once to the tracked blocks undo stack. Changing flavour creates a fresh block for live JS models. Edits within a flavour retain the block identity. Cross-block deletion, IME preview and clipboard slices follow the full tree order within Page-visible notes, including collapsed content. Subtrees after the endpoint survive. A range starting in code places those subtrees immediately after the code block. Numbered Markdown lists accept zero as a starting number and continue a preceding numbered sibling when present. Typing within the 500 ms scheduler-clock capture window coalesces. Undo and redo resolve stored relative positions in the title or block text. Local commits publish document updates and selection changes publish awareness under `<pageId>:native`; a selection that is dropped publishes that entry empty, so peers stop drawing the caret and keep the name and color. Preedit temporarily replaces the selected text in the displayed snapshot. Cancellation restores the directional range. Only a commit writes text. Editing the page title also updates workspace page metadata.
- Clipboard slices carry BlockSuite JSON, HTML and plain text. macOS publishes UTF-8 text and `public.html` and reads HTML-only pasteboard items. Web clipboard events expose HTML and the BlockSuite MIME type. HTML includes the LZ-String URI-encoded `data-blocksuite-snapshot` for lossless block properties, child blocks and inline references. The slice preserves shared text types in nested properties. Pasting into one text block preserves relative positions in its untouched suffix.
- A text-only edit refreshes the changed block's text and reuses the other laid-out bodies. Remote updates preserve the screen position of the reading anchor when its block survives. On Linux headless with 10,000 blocks at 1280 × 800, cold layout and frame took 284.078 ms median / 328.501 ms p95. A keystroke in paragraph 5000 and its frame took 17.793 / 19.454 ms and laid out one block. A steady viewport frame including pixel readback took 10.691 / 16.928 ms. These are observed timings. The single-block work count is enforced by the benchmark.

### Overlays and block controls
- **Who owns what**: `EditorSession` owns the text selection, the caret and every text edit. `Overlays` (`overlays.rs`) owns what floats above or reacts inside the page: the slash menu, the formatting toolbar, the drag handle with its drop indicator, hover, and the block controls. The overlays read the selection (as a `SelectionFormat`: its world-space box, the marks every selected unit carries, the shared alignment) and never paint a caret or a selection of their own.
- **Data in, commands out**: `Overlays` takes an `OverlayScene` (page snapshot, world-space layout, window geometry) with an `OverlayEvent` or a key, and answers with `OverlayEffects`. The `PlaygroundView` glue at the end of `overlays.rs` feeds it input and carries the effects out; `lib.rs` and `block_flow.rs` only carry hooks (`PagePaint` into `page_elements`, the page-layer elements and popovers into the element tree, listeners). `PlaygroundView::dispatch_overlay` is the entry for pointer listeners and for hosts and tests (`OpenSlashMenu`, `SetSlashQuery`, `SetSelection`, ...); `SetSelection` sets the editor's selection.
- **Pointer and keys**: A press on the page dismisses the slash menu, the link field (unapplied) and a block drag, then goes to the editor; pointer moves and the release are handled at the window root, so a drag continues outside the page. The formatting toolbar waits while the button of a plain press is held and opens on release; a double or triple click opens it at once. Keys reach one handler, `editor_key_down`, which first offers them to the overlays: an open link field takes every key but the ones that type text, the slash menu takes `Up`, `Down`, `Tab`, `Shift+Tab`, `Enter` and `Escape` (`Tab` steps through the items and never indents the block; `Enter` without a match closes the menu and does not split the block), and everything else is the editor's. A pointer on an open popover does not change which block is hovered under it.
- **Edits are single undo steps**: Every overlay edit goes through the editor's `PageDocSession`, stores the selection for undo, and is published like any editor commit. Marks use the editor's `format_mark`; a link and an alignment run in one `structural_edit` across the selected paragraph and list blocks; a to-do box, a collapse and a drop are isolated between `stop_capturing` calls, the drop through `reparent_block` so numbered runs are renumbered. A slash command is one `structural_edit`, following BlockSuite's `updateBlockType` and `appendDivider`: it removes the typed `/filter`, then a paragraph type, a list type or code converts the block with whatever text it has left (in place within a flavour, as a fresh block across flavours; a block without text of its own gets the new block below instead), and a divider goes right below the block, followed by an empty paragraph to type in when the block was the last of its parent. The caret stays where the command was typed, or moves to the block after a divider. One undo restores the typed command.
- **Positioner**: `place_popover` is pure and works in screen space below the top bar: `Above` (formatting toolbar, centered on the selection) and `BelowStart` (slash menu, at the caret) flip to the other side when the preferred one would come closer than the edge margin to the top bar or the window bottom, and clamp horizontally inside the margins. Results are on the pixel grid.
- **Overlay motion**: Popovers fade over 150 ms with an ease-out cubic `EaseOut` evaluated at scheduler time. An opening popover mounts on its first frame at zero opacity so its hitboxes are live immediately; a closed popover at zero opacity is unmounted, and one fading out carries no listeners and is dropped when the fade ends. Disclosure chevrons turn over the same 150 ms. Nothing here loops per frame.
- **Slash menu** (`overlay.slash_menu`, rows `overlay.slash_menu.item.<id>`, `.group.<name>`, `.query`, `.empty`): Typing `/` at a caret in paragraph or list text, outside inline code, opens it on that character, remembered as a relative position (`EditorSession::slash_trigger`): text a peer inserts before the `/` moves the menu along. The text between the `/` and the caret is both document text and the filter (`query_in_document`); the menu closes when the caret leaves that text, whitespace follows the `/`, or the character at the position is no longer that `/` (deleted, or deleted and typed again by a peer), and a command never runs on text it did not open on. `Escape` leaves the text as typed. `OpenSlashMenu` opens the menu with a filter of its own, shown in a query row and edited by the menu's keys. Without matches the list keeps a `No results` row. Items follow BlockSuite's order in two groups (`Basic`: text, the six headings, code block, quote, divider; `List`: bulleted, numbered, to-do, toggle); all six headings stay in the list itself so each is one filter away. Each icon sits in a bordered 28 px box, rows are 32 px, and the menu has no border, only its shadow.
- **Formatting toolbar** (`overlay.format_toolbar`, buttons `.bold`, `.italic`, `.underline`, `.strike`, `.code`, `.link`, `.align_left|center|right`, link field `.link_input`, `.link_apply`, `.link_remove`): shown above a finished, non-empty selection of paragraph and list text, single-block or across blocks, while no composition runs and no slash menu is up; a selection touching the title or code gets none. A mark button is active only when the whole selection carries the mark. Alignment goes on every paragraph and list block the selection touches, empty ones included, and a block that sets none reads as its nearest aligned ancestor's. The link field is a one-line text input of its own (`LinkBar`: text, selection, composition). While it is open it is the view's text input: every `EntityInputHandler` call goes to it, `editor.composing()` stays false, and the document's text, selection and composition are untouched until `Apply`; opening, closing and every change of it are reported with `notify_text_input_changed`. Caret keys, deletion, select-all, copy and cut are the field's, `Escape` abandons a composition before it closes the field, and a keyboard paste reads the clipboard where the platform can; in a browser the key keeps its default action so the `paste` event that follows reaches the field. It has the only caret; the document keeps showing the selection.
- **Drag handle** (`overlay.drag_handle`, `overlay.drop_indicator`): mounted only for the hovered or dragged block, 24 px left of the block and never closer than 4 px to the window edge. Inside its 24 px target it draws BlockSuite's grabber: a 4 × 12 px bar while the pointer is on the block's row, and two columns of three dots on a 14 px pill once the pointer is on the handle or drags it. A heading keeps the place beside its text for its collapse chevron: its handle sits one step further out, and is left away where the gutter has no room for both. A drag targets the nearest slot among the block's own siblings.
- **Block controls**: `page.block.<id>.checkbox`, `.toggle` and `.collapse` are 24 px targets over the to-do box, the toggle chevron and the heading chevron (an expanded heading shows its chevron only while the pointer is on its row); `page.block.<id>.copy` appears on a hovered code block and reads `Copied` for 1.5 s on the scheduler clock. A sideways scroll over an unwrapped code block scrolls its lines inside `BlockBody::code_scroll` instead of the page; the caret, the selection, the bounds given to the input method, collaborators' carets and selections, and pointer hit-testing follow that scroll and stay inside the code area (`ScrolledCode`), and moving the caret scrolls it into view.
- **Sizes and radii**: Interactive targets are at least 24 × 24 px (toolbar buttons 28 × 28, edge to edge). Rows and buttons round concentrically with their container: 8 px menu with 4 px padding and 4 px rows (BlockSuite pads its menu `8px 4px 8px 8px`; 4 px all around keeps the radii concentric), 8 px toolbar with 4 px padding and 4 px buttons. The toolbar is 297 px wide, with 8 px on either side of the line between the mark and the alignment buttons, and fits a 320 px window between its 8 px margins.
- **Verification**: `bs-harness render --state <name>` renders one overlay state of the showcase, `bs-harness audit-states` audits every state in both themes at `1280` and `320` px, and `bs-harness record-demo <dir>` writes the frames of a 60 fps walk through typing, composition, the slash menu, the toolbar and the block controls; all drive the view through input events, the input handler and `dispatch_overlay` only.

### Performance guardrail and theme/style oracle
- **`perf/` (`schema.json`, `accepted.json`, `compare-n3.mjs`, `compare-n3.test.mjs`)**: Zero-dependency rolling `N-3` CI comparator with strict schema validation and rerun history anchoring (`--run-id` `created_at` cutoff + pagination). Deterministic byte sizes (`artifacts_bytes.*`) and work counters (non-`_ms` `benchmarks.*`) are hard-gated at strictly `> 10%` (`--fail-on-regression` exits `1`); shared-runner wall-clock timings (`benchmarks.*_ms` at `> 10%`, `ci_wall_ms.*` at `> 10%` and `> 15_000 ms`) are report-only `ADVISORY_SLOWDOWN`. Intentional increases are acknowledged via `{ metric, accepted_value, reason }` ceiling entries in `perf/accepted.json` (with report-only `stale_acceptances` once the rolling baseline catches up). Unmeasured sub-keys are omitted or `null` (never padded with synthetic `0`s) so newly introduced metrics transition through `BOOTSTRAP`.
- **`tokens/` (`extract-tokens.mjs`, `tokens.rs`, `icons.rs`, `fonts.lock`, `extract-style-oracle.spec.ts`, `style-oracle.json`)**: `extract-tokens.mjs` deterministically generates Rust-`Ord`-sorted `tokens.rs`, `icons.rs` (preserving inherited `<svg fill>` and stroke attributes), and `fonts.lock` (SHA-256 font asset manifest + `CommunityCanvasTextFonts` descriptors), with `--check` and `rustc --edition 2024 --test` enforced on every push in CI. `style-oracle.json` is regenerated via Vitest Browser (`extract-style-oracle.spec.ts`, `isolate: false` reusable iframe) whenever BlockSuite styles or themes change (until its browser CI job lands).

### Rich paragraph layout
- **Variable-font slant axis**: CoreText and Swash specialize an upright variable face at its minimum OpenType `slnt` coordinate for italic and oblique requests, alongside `wght`. A native static italic face retains its own outlines. Pixel letter spacing shifts shaped clusters and their total advance together.
- **`RichParagraph`**: The single rich-text engine: `BlockFlow` lays out and paints paragraph and list text with it (`LaidOutRichParagraph::paint_at`, the same path `RichParagraphElement` uses), and reads remote carets and selections from its geometry. Cursor and selection geometry uses source UTF-16 positions and extended-grapheme boundaries. Each inline reference occupies one document unit regardless of its resolved label width, wraps as one inline object (the words before it stay on their line), and its prefix is the generated `LinkedPageIcon` SVG painted at the `DecorationKind::PageGlyph` bounds. `color` and `background` marks resolve through the theme (`DecorationKind::Highlight` behind the glyphs), and bold follows CSS `bolder`. Shaped lines supply wrapping, painting, hit targets, and both caret affinities at a soft wrap.
- **Inline style parity**: Code boxes and links follow the light/dark theme tokens and browser measurements in `tokens/style-oracle.json`; the code box metrics are constants that a test keeps equal to the oracle, so the oracle JSON is never embedded in the shipped binary. Plain and rich renders of one document can be reproduced with `bs-harness render-rich-sample --out-plain plain.png --out-rich rich.png`.

### Edgeless rendering and GPU transforms
- **End-to-end GPU transforms and local clip masks**: `Window::with_paint_transformation` composes 2D affine transforms (`TransformationMatrix`) on a stack and `Window::with_local_paint_mask` intersects pre-transform local clip rects (`ContentMask<Pixels>`). All GPU primitives (`Quad`, `Shadow`, `Underline`, `MonochromeSprite`, `SubpixelSprite`, `PolychromeSprite`, and `PathRasterizationVertex`) are 16-byte aligned (`size_of % 16 == 0`, verified by compile-time assertions) for WebGL2 `RGBA32U` instance-texture decoding. Both Metal (`shaders.metal`) and wgpu/WebGL2 (`shaders.wgsl`, `shaders_webgl.wgsl`, `shaders_subpixel.wgsl`) transform vertices on the GPU, evaluate SDFs in local space scaled by `transform_scale` for 1-device-pixel anti-aliasing across zooms and rotations, and clip against both screen-space `content_mask` and pre-transform `local_content_mask`.
- **Quarter-octave glyph zoom bucketing**: Under non-unit paint scales, `Window::paint_glyph` and `Window::paint_glyph_in_run` quantize rasterization scale to quarter-octave buckets (`2^(round(4*log2(s))/4)` clamped to `[0.25, 8.0]`), rasterizing atlas tiles at `font_size * bucket` while scaling local quad bounds by `1 / bucket` so cached `1.0x` `RichParagraph` / `BlockFlow` layouts render crisply at `0.1x..6.0x` without re-shaping or relayouting during pan/zoom.
- **Procedural dot-grid (`BackgroundTag::DotGrid = 4`)**: Renders the Edgeless background grid in a single fullscreen `Quad` draw call with 1-device-pixel anti-aliased dots anchored to world `(0, 0)` and spacing matching BlockSuite's `getBgGridGap(zoom)`.
- **Spatial camera & canvas**: `edgeless_camera.rs` (`EdgelessCamera`) manages pan/zoom (`[0.1, 6.0]`), cursor-anchored wheel zoom, and fit-to-bounds. `edgeless_canvas.rs` renders `affine:frame`, `affine:note` (each backed by a cached `BlockFlow::layout_nodes` with zero relayout during pan/zoom), and rotated/scaled `affine:edgeless-text` under `edgeless.viewport`, with bottom-right screen-space zoom controls (`chrome.edgeless_zoom`). `bs-harness render --mode edgeless [--zoom <f32>] [--pan <x>,<y>]` renders spatial states, `bs-harness audit-states` audits Edgeless default + `0.5x` + `2.0x` in Light/Dark at `1280` and `320` px, and `bs-harness bench` measures `edgeless_1k_pan_zoom_frame_ms` and asserts `edgeless_1k_pan_zoom_blocks_relayout == 0`.
